# 工业指示灯检测系统 (light_check)

固定摄像头场景下，检测设备箱放入槽位后绿灯的工作状态：
- **闪烁 (flashing)** = 正常工作
- **常亮 (steady_on)** = 故障
- **不亮 (off)** = 故障

## 快速开始

```bash
pip install -r requirements.txt

# 测试视频1（异常-灯不亮）：从第450帧(9s,画面稳定处)开始
# 默认会把标注视频输出到源视频同级目录：<video_name>_annotated.mp4
python main.py --config config_off.json --start 450

# 测试视频2（异常-灯长亮）：从第350帧(7s,画面稳定处)开始
python main.py --config config_on.json --start 350

# 测试视频3（正常起落-近点）：从第2250帧(45s)开始，测完整入槽+正常闪烁
# 启用入槽检测(亮度法)，设备入槽后灯由不亮转闪烁
python main.py --config config_near.json --start 2250

# 无界面运行（服务器/批量），仅输出控制台与CSV日志（仍会输出标注视频）
python main.py --config config_off.json --no-show --start 450

# 不输出标注视频
python main.py --config config_off.json --start 450 --no-save

# 指定标注视频输出路径
python main.py --config config_on.json --start 350 --save-annotated /path/to/out.mp4
```

运行时窗口中按 `q` 退出，空格暂停/继续。最终会在控制台汇总每个 ROI 的判定结果与期望是否一致，并把逐跨度判定写入 `logs/<视频名>_<时间>.csv`，标注视频默认写入源视频同级目录。

## 文件结构

| 文件 | 作用 |
|---|---|
| `light_classifier.py` | 灯状态分类纯函数（绿色超出量 + 振荡次数），含单元测试 |
| `slot_detector.py` | 核心检测器：状态机、信号提取、跨度判定、多跨度投票、可视化叠加 |
| `main.py` | 主程序：参数解析、视频循环、控制台/CSV日志、显示与导出 |
| `config_off.json` | 视频1配置（异常-灯不亮） |
| `config_on.json` | 视频2配置（异常-灯长亮） |
| `config_near.json` | 视频3配置（正常起落-近点，含入槽+正常闪烁） |
| `requirements.txt` | opencv-python, numpy, scipy |
| `logs/` | 运行日志（CSV） |

## 与原设计文档的关键差异（经实测验证）

原设计文档提供了完整框架，但在两个真实测试视频上发现若干假设不成立，已做如下调整。**这些调整都基于对实测数据的统计分析，详见下文"标定依据"。**

### 1. 信号选择：ROI 内"亮像素 green_excess 均值"，而非全框均值或 G 通道绝对亮度

- **green_excess = G - max(R, B)**：绿灯发光时 G 明显大于 R、B，灰色背景/环境光 green_excess≈0。环境光是三通道同步变化，green_excess 天然免疫，无需再做 roi-ref 相减。
- **取"亮像素均值"而非"全框均值"（关键，解决新批视频稀释问题）**：
  - 实测当 **ROI 框比灯体大很多**时（如新批视频 lower 框 120×103、灯体仅 35×21，亮像素占框 3%），全框均值会把灯的高 green_excess 与大量背景的 0 平均掉，稀释成 median≈-2 → 误判 off/unknown。
  - 改取 ROI 内 `green_excess > lit_thr`(默认15) 的**亮像素均值**（无亮像素则 0），只取灯体亮像素，信号不被稀释。新批视频 lower 由此 median≈35、osc≈8 → 正确判 flashing。
- **面积门区分"反光"与"真灯"**：亮像素均值会捕获框内局部绿色反光（如旧视频 fault_off 处的持续反光 ge≈18）。实测反光亮像素面积小（≈60px）、真灯面积大（≈412-914px），差 7-15 倍。故跨度内**亮像素面积中位数 > `area_min`**(默认150) 才算真灯，否则判 off。这同时让"空槽"(面积0)判 off。
- **灰度门区分"不亮"与"常亮"（视频3实测发现，关键）**：视频3中"不亮"故障并非"无绿色"——设备入槽后绿灯**外壳本身是绿色**（ge≈31，面积≈450），与"常亮"（LED 点亮 ge≈34）的 green_excess 几乎相同（`max(R,B)` 抹平了 LED 点亮带来的 G 通道提升），无法用 ge 区分。但 **LED 点亮会显著照亮整个 ROI**：不亮灰度≈51，常亮灰度≈110，差 2 倍。故"真灯+不振荡"时用 **ROI 灰度中位数 ≥ `gray_thr`**(默认80) 判常亮，否则判不亮。振荡分支(闪烁)不看灰度（亮暗态灰度跨度大，中位数无意义）。
- **判定流程**：`面积不够 → off`；`真灯 + 振荡(osc≥osc_min) → flashing`；`真灯 + 不振荡 + 灰度高(≥gray_thr) → steady_on`；`真灯 + 不振荡 + 灰度低 → off(外壳绿LED未亮)`。

### 2. 闪烁判定：振荡次数，而非 FFT 频率匹配

- **问题**：实测正常绿灯是不规则的"开/关阶跃"，大部分时间高亮度、偶尔跌落到接近 off 再回升，**无固定频率**，FFT 主频能量极低(0.09~0.15)。原设计的 `flash_freq_range=[2,10]` FFT 匹配会把正常灯判成 `unknown`。
- **解决**：用"振荡次数"判据——序列 25/75 百分位差作为振幅门限（小于门限=无波动），再以 (p25+p75)/2 为分界统计平滑后序列的穿越次数。闪烁→多次跳变；常亮/不亮/瞬态突起→0~1 次跳变。FFT 仍计算但仅写入日志，不参与判定。

### 3. 入槽检测：面积法（固定摄像头现场监控）/ 亮度法（手持测试视频）

- **问题**：原设计用背景差分检测设备入槽，需视频开头为空槽；且用户要求**不能用灯亮作为入槽标准**（入槽出错会导致灯不亮，需仍能检测到入槽以报故障）。
- **面积法 `enter_method: "area"`（视频3起，固定摄像头现场监控推荐）**：
  - 实测灰度法在固定摄像头现场**不可用**：机械臂移动经过空槽时灰度升高（误判入槽）、设备空中停留灰度更高（误判）、不同槽空槽灰度差异大（33~90，无统一阈值）。
  - 设备入槽后，灯体（**LED 点亮或仅绿色外壳**）在 ROI 内带来稳定绿色面积（>100px），且真在槽时面积基本不归零（闪烁暗态面积仍>200）；机械臂移动经过空槽时绿色面积短暂出现又归零（持续<0.5s）；空槽时面积恒为 0。
  - 故用"**连续 `enter_frames` 帧(默认25) green_excess 亮像素面积 > `area_thr`**"判入槽——连续性可过滤机械臂经过的瞬态（持续<enter_frames 帧）。不依赖灯是否点亮（外壳绿也有面积），能覆盖"入槽出错灯不亮"。
  - **出槽判定**：每帧检查绿色面积。面积基本归零（窗口超阈占比≤`leave_ratio`），或当前面积显著低于入槽稳定值（<`stable_area * leave_drop_ratio`，设备正在离开）即判出槽、reset 回 WAITING。用稳定值比较可提前判出槽，不必等完全归零。
- **亮度法 `enter_method: "brightness"`（手持测试视频用）**：实测空槽时灯ROI是最暗稳定态（灰度≈74），设备箱进入后变亮（灰度≈93~130），无论灯亮与否。用滑动窗口低百分位作空槽基线，当前灰度持续超 `基线 + margin` 判入槽。出槽用入槽时冻结的基线快照比较。
  - 注意：手持视频适用；固定摄像头现场不可用（见上）。
- **保留背景差分法**：`enter_method: "bg_diff"` 仍可用（适合视频开头确为空槽且固定摄像头的场景）。
- **`skip_enter`**：跳过入槽检测直接进入 DETECTING，用于设备已在位的手持测试视频（config_off/config_on）。
- **短时在槽的紧急判定**：设备在槽时间不足 `span_size` 攒满投票就出槽时，用已有帧(≥60)补一次判定；仅在信号明确时确认（osc≥osc_min 判闪烁，或面积门判 off），steady_on 不确认（短跨度易误判）。这覆盖"在槽仅2~3秒"的边界情况，同时避免误判。

### 4. 参考框：已移除（实测无效）

- 历史上曾引入参考区(ref)做自适应阈值 `on_thr = max(on_threshold, ref_ge_median + on_margin)`，但技术报告（TECH_REPORT.md）实测确认其**无效**：
  - ref 区是中性环境（无绿色物体），ref_ge 恒为负，`ref_med+margin` 永远低于固定 `on_threshold`，自适应阈值退化为固定值。
  - 且面积门模式下 `on_thr` 结构性不参与判定（判定只用面积门+振荡门）。
- 故**移除 ref**：删除 `ref_roi` 配置、`_ref_ge`/`_ref_mean` 方法、ref 信号采集、CSV 的 ref 列。`green_excess` 天然免疫环境光（三通道同步变化相减抵消），无需参考区。`on_threshold` 保留为固定阈值（面积门模式下也不参与判定，仅退化模式/单元测试用）。

### 5. 入槽检测：每 ROI 独立状态机（多槽位部署刚需）

- **问题**：旧版 SlotDetector 是单状态机，`_check_enter_brightness` 用 `any(entered)` 让任一 ROI 触发就全进 DETECTING。多槽位场景下一个槽入槽会连累其他槽提前进检测，失效。
- **解决**：每个 ROI 封装为 `PerLightState` 对象，独立维护 state/入槽计数/信号缓冲/确认状态。各槽独立 WAITING→DETECTING→WAITING，互不干扰。单 ROI 退化为 `lights[0]`，行为不变。
- 取走判定(`leave_check`)也每 ROI 独立：一槽取走不影响他槽（旧版 `all_left` 要求全部取走才回 WAITING，多槽位下不合理）。
- `process_frame` 返回 `states`（每 ROI 状态列表）而非单一 state。

### 6. 滑动跨度 + 多跨度投票，而非单窗口

- **问题**：单个短窗口(如40帧)可能恰好落在闪烁的某段电平内，误判为常亮；且故障灯状态会随时间变化（视频2：闪烁→常亮）。
- **解决**：用较长跨度(默认150帧≈3s@50fps)做最终判定，跨度按步长(默认25帧)滑动，输出状态时间序列；连续 `confirm_spans`(默认2) 个跨度一致才更新确认状态，抑制瞬态。

## 标定依据（实测数据，绿灯 G 通道 / green_excess，0-255）

| 场景 | G通道均值 | green_excess 中位数 | 振荡次数(跨度) |
|---|---|---|---|
| 正常闪烁(视频1) | 168 | 9 | 7~10 |
| 正常闪烁(视频2) | 111~155 | 9~15 | 8 |
| 正常闪烁(视频3,入槽后) | 98~132 | 12~14 | 8 |
| 不亮(视频1,稳定段) | 65~88(早期) / 灰背景≈109 | **0** | 0 |
| 常亮(视频2,稳定段) | 120~127 | 15~16 | 0 |

入槽检测标定（视频3，灯ROI灰度）：

| 阶段 | 灯ROI灰度 | 说明 |
|---|---|---|
| 空槽(45s) | 74 (std 0.7) | 最暗稳定态，作为基线 |
| 设备入槽中(46-50s) | 66~147 波动 | 设备箱进入，区域变亮 |
| 入槽后灯未亮(50-51s) | 96~100 | 设备在位、灯未亮（**亮度法仍判入槽**，不依赖灯亮） |
| 灯闪烁(51s+) | 98~130 交替 | 灯亮起，green_excess 跳变 |

据此设定 `enter_brightness.margin=15`（空槽74 + 15 = 89，设备存在≥93 可区分）。

据此设定默认阈值（可在配置 `classifier` 中调整）：
- `on_threshold = 5.0`：green_excess 中位数低于此值视为不亮（off≈0，亮灯≈9~16）。
- `osc_min = 6`：跨度内有效跳变次数阈值（闪烁≈5~29，稳态/不亮≈0~1）。
- `min_sep = 4.0`：振幅门限，green_excess 序列 25/75 百分位差小于此值视为无波动（视频2弱闪烁振幅≈6~7，需降到4才能识别；稳态/不亮振幅≈0~2 仍被正确抑制）。
- `smooth_kernel = 5`：中值滤波核，抑制逐帧噪声造成的虚假跳变。

## 坐标说明

用户提供的检测框坐标为 **0~100 的归一化百分比**。配置中 ROI **只需写 `norm` 的 X/Y/W/H**，绝对像素坐标 `x/y/w/h` 由代码按 `image_size` 自动转换（无需手填）：

```json
"roi_list": [
    {"name": "light", "norm": {"X": 51.31, "Y": 49.28, "W": 2.99, "H": 4.96}, "expected": "steady_on"}
]
```

转换公式（按 config 的 `image_size`，默认 1920×1080）：

```
x = round(X/100 * img_w),  y = round(Y/100 * img_h)
w = round(W/100 * img_w),  h = round(H/100 * img_h)
```

> 兼容：若 ROI 同时含 `x/y/w/h`（旧 config）则直接用，不覆盖。
> ⚠️ 视频手持拍摄存在画面摇晃，给定的 ROI 坐标仅在画面稳定段准确，建议用 `--start` 跳过晃动段（视频1从450帧/9s，视频2从350帧/7s，近点从2250帧/45s）。

## 可视化展示（出入槽 + 灯状态）

标注视频每个 ROI 框展示**出入槽状态 + 灯状态**，只区分两种出入槽状态（不展示"等待/检测中"中间态，由算法自行判断）：

- **已入槽**（设备在槽，DETECTING 状态）：框颜色随灯状态（绿=闪烁/黄=不亮/红=常亮/灰=待定），灯状态随跨度判定逐步更新。入槽后到判出灯状态前显示"已入槽:待定"（约1-3秒，攒满跨度才判振荡）。
- **已出槽**（设备不在槽，WAITING 状态）：框保留最近一次在槽判定的颜色 + "已出槽"标签，便于回溯该槽最后判了什么。从未入槽的槽显示"已出槽:待定"（灰）。

标签格式：`槽名 灯状态(已入槽/已出槽)`，如 `slot2_off 不亮(已入槽)`、`slot1 闪烁(已出槽)`。顶部状态条显示每槽 `槽名:已入槽/已出槽`。

中文用 PIL + 微软雅黑渲染（cv2.putText 不支持中文会显示 `?`）；无 Pillow/中文字体时退化为英文 cv2.putText。

## 后续优化方向

- **固定摄像头部署**：去掉 `--start`，设 `skip_enter=false` 启用入槽检测，状态机自动 WAITING→DETECTING→WAITING（每 ROI 独立）。
- **ROI 自动定位**：固定摄像头下可结合模板匹配自动定位每个槽位绿灯，避免手填坐标。
- **阈值现场标定**：不同 LED/环境下 green_excess 量级可能不同，可采集一段已知状态视频后用 `light_classifier.py` 的统计量微调 `on_threshold`/`min_sep`。
